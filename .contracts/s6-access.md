# s6-access — вход по паролю, закрытие доступа и публикация

## Пути

Появляются:

    middleware.ts                     закрытие по умолчанию: всё, кроме списка исключений
    app/login/page.tsx                страница входа
    app/login/action.ts               серверное действие входа
    lib/auth/session.ts               подпись, проверка и срок жизни cookie
    lib/auth/password.ts              стойкое ко времени сравнение пароля
    __tests__/auth/*                  проверки входа и закрытия
    __tests__/live/access.live.ts     проход целиком снаружи, без cookie
    breaks/s6-access.ts               список сломов куска

Правятся:

    lib/ingest/google-access.ts       приём ключа значением — добавлением, см. отступление 1
    app/page.tsx                      перехват отказа сужается, см. входящую задачу
    README.md                         вход, публикация, переменные

Не открываются: `lib/facts/**`, `lib/metrics/**`, `lib/ingest/**` кроме названного файла,
`supabase/migrations/**`, `supabase/seed.sql`, `vitest.config.ts`, `.github/workflows/ci.yml`,
все проверки S1–S5.

## Результат

Дашборд доступен по адресу в интернете и закрыт паролем. Человек без пароля не видит ни
экрана, ни чисел — ни на странице, ни через серверное действие кнопки. Кнопка «Обновить
данные» работает в бою по-настоящему: доходит до Google и до боевой базы.

## Что известно на входе — разведка

Разведана голова `cfcc2f6` (S5 слит в main).

### Пути, отдающие числа или запускающие работу

| Путь | Где | Что отдаёт | Сегодня |
|---|---|---|---|
| `GET /` и `GET /?m=ГГГГ-ММ` | `app/page.tsx` | полный отчёт месяца | открыт всем |
| Серверное действие кнопки | `app/refresh-action.ts` | не отдаёт, но **пишет**: перечитывает оба источника и пересобирает факты | открыто всем |
| `GET /health` | `app/health/page.tsx` | номер коммита сборки | открыт всем |

**Отдельных адресов для чисел в проекте нет.** Ни одного обработчика маршрута, ни одного API.
Страница и есть тот «адрес, по которому страница берёт числа», о котором говорит приёмка 4.

### Что есть про доступ к базе

Роли `anon`, `authenticated`, `service_role` заведены миграцией S1 под `if not exists`, но
**ничем не наделены и ничем не ограничены**: во всех миграциях нет ни одного `grant`, ни одной
политики, ни одного `enable row level security`. Единственные права — два `revoke all on schema
… from public` на `raw` и `fact`.

Это не дыра, и вот почему. Приложение говорит с базой **напрямую через `pg`** по адресу из
`SUPABASE_DB_URL`, минуя PostgREST, публичный ключ и роли Supabase целиком. Схемы `raw` и
`fact` наружу не выставлены. То есть путь «прочитать данные публичным ключом из браузера»,
которого опасался контракт S1, в этом устройстве не существует вовсе.

Экран и загрузки ходят в базу **одним и тем же** способом и под одним и тем же пользователем:
`resolveIngestTarget()` в `lib/ingest/target.ts`. Отдельного, более узкого доступа для чтения
у экрана нет.

### Что есть про публикацию

Ни `vercel.json`, ни шага выкладки в `ci.yml`. Контракт S0 объявляет подключение к Vercel
ручной работой владельца вне репозитория. `/health` берёт номер коммита из
`VERCEL_GIT_COMMIT_SHA`, при пустой — из `git rev-parse HEAD`, иначе печатает «неизвестно».

### Переменные окружения, которые проект читает сегодня

| Переменная | Где читается | Что без неё |
|---|---|---|
| `NORDIC_PET_DB_TARGET` | `lib/ingest/target.ts` | отказ до всякой работы |
| `SUPABASE_DB_URL` | `lib/ingest/target.ts` | при `production` — отказ |
| `SUPABASE_DB_CA` | `lib/ingest/target.ts` | берётся системная корневая; для нашей базы этого мало — проверено живьём |
| `DATABASE_URL` | `lib/db-url.ts` | берётся местный адрес по умолчанию |
| `VERCEL_GIT_COMMIT_SHA` | `lib/commit.ts` | откат на `git`, затем «неизвестно» |
| `GOOGLE_APPLICATION_CREDENTIALS` | внутри `google-auth-library` | авторизация Google не соберётся |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | `lib/ingest/sheets-source.ts` | неизвестно, какую Таблицу читать |
| `GOOGLE_DRIVE_ADS_FOLDER_ID` | `lib/ingest/drive-source.ts` | неизвестно, какую папку читать |

### Находка разведки: три мёртвые переменные

В `.env.local` лежат `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY` и
`SUPABASE_SERVICE_ROLE_KEY`. **Их не читает ни один файл проекта.** Последняя — ключ, обходящий
любую защиту строк. Лежит без дела. Задача этого куска — убрать их из `.env.local` и назвать
это в теле pull request; в код они не вводятся.

## Решения владельца, принятые до работы

### Решение 1: вход свой, не заёмный

Логин и пароль живут в переменных окружения; страница входа выдаёт подписанную cookie; всё,
кроме списка исключений, закрыто проверкой до всякой работы.

Supabase Auth отвергнут владельцем: он тянет вторую библиотеку, второй способ говорить с базой
и таблицу пользователей, которых никто не просил, ради одного общего входа. Защита
развёртывания Vercel отвергнута: это не вход в дашборде, а приёмка смотрит, закрыт ли доступ
**нашей работой**.

Требования к устройству, названные владельцем дословно:

| Требование | Почему |
|---|---|
| cookie `HttpOnly`, `Secure`, `SameSite` | иначе её прочитает сценарий на странице или утащит чужой сайт |
| срок жизни назначен **явно** и назван в контракте с доводом | взятый наугад срок — это решение, которое никто не принимал |
| подпись секретом из переменной окружения; секрета нет в коде и в репозитории ни в каком виде | секрет в git — секрет, которого больше нет |
| сравнение пароля **стойкое ко времени** | посимвольное сравнение выдаёт длину совпавшего начала |
| проверка **на каждом пути**, а не одна в общем месте | «через которое все ходят» — это допущение, которое завтрашний путь нарушит |
| ни пароль, ни секрет подписи не попадают ни в один текст отказа и ни в один журнал | отказ уходит в чужие руки |
| неверный пароль отвечает одинаково на любой ввод | иначе ответ подсказывает, что именно не совпало |

**Срок жизни cookie — двенадцать часов, и вот довод.** Дашборд смотрят рабочими подходами, а
не держат открытым неделями; двенадцать часов покрывают рабочий день с запасом и не переживают
ночь. Меньше — человек будет входить посреди работы; больше — забытая вкладка на чужой машине
остаётся входом дольше суток. Число названо здесь, чтобы его можно было оспорить, а не
обнаружить в коде.

### Решение 2: устройство закрывает по умолчанию

Не «закрываем перечисленные пути», а **«закрыто всё, кроме перечисленных исключений»**. Слова
владельца: в первом случае завтрашний путь открыт по забывчивости, во втором — закрыт, пока
кто-то сознательно не впишет его в список.

**Список исключений сегодня из одной строки: `/health`.**

`/health` остаётся открытой потому, что отдаёт только номер коммита — не экран и не данные, —
а своё единственное дело с S0, отличать «выложилось новое» от «браузер показал старое», за
паролем делать не сможет. Плюс страница входа, которая исключением не является: она ничего не
отдаёт и существует ради того, чтобы получить cookie.

Три условия владельца:

1. `/health` отдаёт **ровно** номер коммита и ничего сверх. Слом: заставить её отдать
   что-нибудь ещё — обязана покраснеть проверка.
2. Новый путь, не вписанный в исключения, закрыт **сам собой**. Слом: завести путь и убедиться,
   что без записи в списке он требует входа.
3. Решение про `/health` названо в теле pull request и в финальном отчёте отдельной строкой с
   доводом. Открытый адрес без объяснения читается как дыра, с объяснением — как выбор.

### Решение 3: проход целиком снаружи

Приёмка 4 идёт из окна в режиме инкогнито. Значит в куске обязан быть **проход целиком**:
открыть боевой адрес без cookie и показать, что ни экрана, ни чисел не видно. Проверки частей
этого не заменяют — это правило уже стоило проекту дефекта с кнопкой, которая писала данные и
не меняла экран.

## Отступление 1: кусок трогает код S2, и вот причина

**Что происходит.** `GOOGLE_APPLICATION_CREDENTIALS` — это **путь к файлу**, а не сам ключ. Так
сказано в документации Google: «store the path to this file in the `GOOGLE_APPLICATION_CREDENTIALS`
environment variable». На Vercel файла с ключом нет и положить его некуда. Значит кнопка в бою
до Google не дойдёт, а приёмка 3 звучит дословно: «нажмёшь Обновить — и покажешь, что
изменилось».

**Чем закрывается.** Документация той самой библиотеки, которой мы пользуемся
(`google-auth-library` для Node.js), описывает приём ключа **значением**:

> Instead of loading credentials from a key file, you can also provide them using an environment
> variable. This is particularly convenient for systems that deploy directly from source control.

и показывает, как: прочитать JSON из переменной и построить клиент `JWT` с полями
`client_email` и `private_key`. Источник назван, из памяти ничего не берётся.

**Форма правки — добавление, а не замена.** Прежний путь через файл остаётся слово в слово;
рядом появляется второй. Условия владельца:

| Условие | Как исполняется |
|---|---|
| Ни одно принятое утверждение S2 не меняется | в проверках S2 удалённых и изменённых строк ноль; доказывается выводом `git diff --numstat`, а не пересказом |
| Способ взят из документации библиотеки, источник назван | назван выше |
| Старшинство при заданных обеих переменных названо **явно** | см. ниже |
| Ключ не попадает ни в один текст отказа и ни в один журнал, даже частью | отказ называет только имя недостающей переменной |
| На каждый путь свой слом | убрал приём значением — покраснела своя; убрал приём через файл — покраснела своя |

**Старшинство: значение важнее пути.** Если заданы обе переменные, берётся ключ из значения, а
путь к файлу не читается вовсе. Довод: значение задают в настройках хостинга под конкретный
боевой запуск, а путь к файлу — это привычка машины разработчика, которая может остаться в
окружении случайно. Старшинство названо здесь, а не оставлено на догадку: молчаливое
старшинство — это будущая беда, которую никто не найдёт. **И оно проверяется:** заданы обе,
файл заведомо негодный, а работа идёт — значит взяли значение.

Отступление уходит в тело pull request названным: кусок S6 тронул код S2, вот причина, вот чем
закрыто.

## Входящая задача из S5

**Перехват отказа на странице шире, чем задумывался.** Он заводился под кривую форму месяца из
адреса, а ловит любой отказ отчёта: при недоступной базе посетитель увидит страницу с текстом
ошибки — без кнопки обновления, без ссылок на месяцы и с кодом ответа «всё хорошо». Найдено
проверкой дельты перед слиянием S5, заведено там задачей и передано сюда владельцем: этот путь
всё равно переписывается под пароль, и чинить его надо тем же движением, а не отдельным кругом.

Что требуется: перехват сужается до отказа по форме месяца, всё прочее летит наружу как
настоящая ошибка; и на этот путь ставится проверка, которой сегодня нет ни одной.

## Что владельцу положить в настройки Vercel — одним заходом

Полный список, чтобы не возвращаться по одной переменной.

| Имя | Что это | Без неё |
|---|---|---|
| `NORDIC_PET_DB_TARGET` | слово `production` | отказ до всякой работы |
| `SUPABASE_DB_URL` | адрес боевой базы вместе с паролём, объединитель в режиме транзакций, порт **6543** | отказ при `production` |
| `SUPABASE_DB_CA` | корневой сертификат Supabase Root 2021 CA, многострочным значением | соединение откажет: `SELF_SIGNED_CERT_IN_CHAIN` — проверено живьём |
| `GOOGLE_SERVICE_ACCOUNT_KEY` | **новая.** Содержимое ключа служебного аккаунта целиком, как JSON | кнопка в бою не дойдёт до Google |
| `GOOGLE_SHEETS_SPREADSHEET_ID` | идентификатор Таблицы | загрузчик не узнает, что читать |
| `GOOGLE_DRIVE_ADS_FOLDER_ID` | идентификатор папки | загрузчик не узнает, что читать |
| `NORDIC_PET_LOGIN` | **новая.** Логин для входа | вход не соберётся: отказ при старте |
| `NORDIC_PET_PASSWORD` | **новая.** Пароль для входа | то же |
| `NORDIC_PET_SESSION_SECRET` | **новая.** Секрет подписи cookie, случайная строка не короче 32 байт | то же |

Ручная работа вне репозитория, тоже одним списком: подключить репозиторий к проекту Vercel;
включить «Enable access to System Environment Variables» (иначе `/health` не узнает номер
коммита); собрать на Node.js не ниже 20.9.

**`GOOGLE_APPLICATION_CREDENTIALS` в настройки Vercel не кладётся** — там нет файла, на который
она указывала бы. Она остаётся способом для машины разработчика.

Каждый отказ, который человек может исправить руками, обязан называть, **что** исправить.
Проверка отказа требует именно нашего отказа, а не любого красного.

## Чего в этом куске нет

- Ролей и прав внутри приложения. Один вход на всех — так сказано в задании.
- Построчной защиты и политик доступа в базе: приложение ходит в базу напрямую через `pg`,
  минуя PostgREST и роли, а схемы `raw` и `fact` наружу не выставлены. Роли из S1 остаются
  заведёнными и ненаделёнными; если однажды появится чтение публичным ключом из браузера,
  вопрос вернётся — и это записано здесь, а не подразумевается.
- Восстановления пароля, второго входа, смены пароля из приложения.
- Правок в счёте, разборе, загрузках и на экране сверх названного.

## Названо вслух

- **Список исключений — единственное место, где кусок может однажды дать течь.** Он короткий
  нарочно, и каждая его строка требует довода в теле pull request. Растущий список исключений —
  признак, что защиту пора пересматривать, а не пополнять.
- **Мы закрываем приложение, а не базу.** Тот, у кого есть `SUPABASE_DB_URL`, ходит в базу
  мимо всякого входа. Это верно и сегодня, и после S6; закрыть базу от владельца адреса —
  другая работа, и здесь она не притворяется сделанной.
- **Три мёртвые переменные убираются из `.env.local`**, включая ключ, обходящий защиту строк.
  Убирается, а не переносится: их не читает ни один файл проекта.

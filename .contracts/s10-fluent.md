# S10 — оформление экрана по Fluent 2

> Контракт. Кода по нему не написано ни строки: он существует, чтобы владелец увидел развилки
> до работы, а не после неё.
>
> Голова, от которой считается кусок: `main`, `d979e62`.
> Снимок «до»: `npm test` — **58 файлов, 743 проверки, код возврата 0** (снято на `d979e62`).

## Цель и жёсткая граница

Требование работодателя: интерфейс должен выглядеть так, как выглядел бы у Microsoft. Кусок
меняет **только то, КАК показано**, и ничего из того, **ЧТО показано**.

Граница записана механически, а не на словах:

| Что не открывается | Как это будет доказано |
|---|---|
| `lib/`, `supabase/`, `scripts/`, `proxy.ts`, `app/health/page.tsx` | `git diff` по списку пуст, код возврата в теле pull request |
| `__tests__/` — все принятые проверки | дифф по каталогу состоит **только из добавленных строк**; ни одной изменённой, ни одной удалённой |
| разметка: `app/page.tsx`, `app/refresh-panel.tsx`, `app/logout-button.tsx`, `app/login/form.tsx`, `app/login/page.tsx`, `app/layout.tsx` | **дифф по ним пуст** — см. «Цена переводов якорей» |

Открывается ровно одно: `app/globals.css`. Плюс новые файлы рядом — проверка стилей, список
сломов `breaks/s10-fluent.ts`, снимки в `docs/screens/`, `README.md`.

### Цена переводов якорей — ноль, и это обязательство, а не надежда

Приборы сломов прежних кусков цитируют разметку побайтно. Я выписал все такие цитаты: **34 якоря**
в файлах `app/`, из них 28 — в `app/page.tsx` и `app/refresh-panel.tsx`. Часть из них цитирует
`<dt>`/`<dd>` вместе с отступом в десять пробелов; любая обёртка вокруг блока сдвинула бы отступ и
порвала бы якорь, о котором никто не думал.

Поэтому кусок берёт обязательство сильнее «двигать осторожно»: **разметка не открывается вовсе.**
Всё оформление делается таблицей стилей по уже существующим тегам и классам. Отсюда:

- переводов якорей — **0**;
- правок принятых проверок — **0** по построению: они читают разметку, а разметка не менялась;
- перепись экрана не может покраснеть от правки вида, потому что видимый текст берётся из
  разметки, а разметка та же самая.

Если по ходу работы окажется, что что-то стилями не выходит, **это находка к владельцу**, а не
решение по дороге. Разметка открывается только с прямого слова.

### Ни одной новой видимой строки на экране

Перепись экрана (`__tests__/screen/census.test.tsx`) утверждает весь видимый текст страницы
списком, по порядку. Любое добавление видимого текста — подпись валюты, поясняющая строка,
текстовая иконка — потребовало бы правки её утверждения, а это прямо запрещено. Значит: иконок
нет, поясняющих подписей нет, декоративных надписей нет. Названо здесь, чтобы соблазн не возник
на середине работы.

## Откуда берётся «как у Microsoft»

Не из моего представления. Три источника, и они разные по весу:

| Источник | Что это | Как я его называю |
|---|---|---|
| `fluent2.microsoft.design` — разделы «Typography», «Layout», «Color», «Elevation» | опубликованная документация Fluent 2 | **справочник** |
| `microsoft/fluentui`, пакет `packages/tokens/src` | исходный текст официальной реализации токенов Fluent 2 | **реализация** |

толкованием отдельных описаний выбирается пример.** Где источники расходятся — сказано, какой
взят и почему.

Всё, что ниже помечено «**вывод наш**», справочником не сказано.

### Тени

> «Fluent uses a set of equations to generate consistent, cohesive shadows based on any given
> value. The shadow ramp references increasing blur values to indicate shadow size and, thereby,
> distance. For example, shadow 2 has 2 pixel blur and shadow 64 has 64 pixel blur.»
> — fluent2.microsoft.design/elevation, раздел «Shadow system»

Условие применения, дословно из таблицы «Low elevation ramp» той же страницы:

> Light · Shadow 4 · «Cards without an edge» · `$shadow4`
> Dark · Shadow 4 · «Cards, grid items, and list items» · `$shadow4`

**Условие, которое нельзя обрезать:** в светлой теме `$shadow4` назван для карточек **без рамки**.

Величины (реализация, `utils/shadows.ts` плюс цвета теней из `alias/*Color.ts`):

```
shadow4 = 0 0 2px <ambient>, 0 2px 4px <key>
светлая: ambient rgba(0,0,0,0.12), key rgba(0,0,0,0.14)
тёмная:  ambient rgba(0,0,0,0.24), key rgba(0,0,0,0.28)
```

### Обозначение фокуса

Сегодня на экране **нет ни одного правила фокуса**. Реализация Fluent даёт форму, которую можно
взять целиком (`react-table/.../useTableRowStyles.styles.ts`, и та же форма у прочих компонентов):

```
outline: 2px solid <StrokeFocus2>;  border-radius: <borderRadiusMedium>;
```
`StrokeFocus2` — чёрный в светлой теме, белый в тёмной, то есть обводка видна на любом фоне.

### Таблица

Из реализации `react-table`:

- высота ячейки: `medium 44px`, `small 34px`, `extra-small 24px`;
- отступы ячейки заголовка `0 8px`, насыщенность заголовка — `fontWeightRegular` (400);
- нижняя граница строки `1px solid NeutralStroke2`;
- наведение на строку: фон `SubtleBackgroundHover`.

### Карточка

Из реализации `react-card`: три размера — `small` (внутренний отступ 8px, скругление
`borderRadiusSmall`), `medium` (12px, `borderRadiusMedium`), `large` (16px, `borderRadiusLarge`).
Вид по умолчанию — `filled`: фон `NeutralBackground1`, тень `shadow4`, рамка прозрачная.

**Пример от Microsoft — CSS самого сайта `fluent2.microsoft.design`:**

```css
.tile {
  background-color: var(--colorNeutralBackground1);
  border: 1px solid var(--colorNeutralBackground1Pressed);
  border-radius: 8px;
  box-shadow: 0 2px 4px #00000024, 0 0 2px #0000001f;
}
```

Здесь скругление `8px` (`borderRadiusXLarge`), рамка есть, и тень — это ровно `shadow4`
(`#24` = 0,141; `#1f` = 0,122). Реализация компонента `Card` для `large` даёт `6px` и рамку
прозрачную. **Источники расходятся**; по записанному выше правилу берётся пример.

Холст приложения: `react-provider/.../useFluentProviderStyles.styles.ts` ставит на корень
`backgroundColor: colorNeutralBackground1`, `color: colorNeutralForeground1`,
`textAlign: 'left'` и типографику `body1`. То есть у Microsoft холст и карточка — **одного
цвета**, а разделяют их рамка и тень.

## Развилки

Каждая меняет результат, поэтому решает владелец. У каждой — моя рекомендация.

### Развилка 1. Холст и карточки: белое на белом, как у Microsoft, — или серый холст, как сейчас

Сегодня: холст серый (`#f4f6f8`), карточки белые, рамка `1px`, тень отсутствует.

- **А (рекомендую).** Как в обоих примерах Microsoft: холст `NeutralBackground1` (белый в светлой
  теме, `#292929` в тёмной), карточки того же цвета, разделяются рамкой
  `1px NeutralBackground1Pressed`, скруглением 8px и тенью `shadow4`. Это буквально то, что делает
  и `FluentProvider`, и сайт Fluent 2.
- **Б.** Холст `NeutralBackground2` (`#fafafa` / `#1f1f1f`), карточки `NeutralBackground1`. Тоже
  из токенов Fluent, ближе к нынешнему виду, но ни один из двух примеров Microsoft так не делает.

**Это самое заметное изменение куска.** Экран станет светлее, и разделять блоки будет тень, а не
цвет фона.

### Развилка 2. Плотность таблицы товаров

Fluent называет три высоты строки: `medium 44px` (по умолчанию), `small 34px`, `extra-small 24px`.
Какую брать для приборной панели, справочник не говорит — **вывод наш**.

- **Рекомендую `small` — 34px.** Это ровно нынешняя плотность; двенадцать товаров занимают около
  408 пикселей вместо 528 при `medium`. Ориентир владельца — «плотность средняя, один-два экрана
  прокрутки».
- Иначе — `medium` 44px: буква Fluent по умолчанию, но экран вырастает примерно на 120 пикселей.

### Развилка 3. Заглавные буквы в заголовках блоков

Сегодня «ВЫРУЧКА», «ЗАТРАТЫ», «ИТОГ» набраны капителью — и этот вид владелец уже принял глазами
на прошлом куске. Справочник Fluent прямо против: «Don't use all caps to get a user's attention
because it's difficult to read.»

- **Рекомендую убрать капитель.** Текст в разметке при этом не меняется ни на символ — капитель
  делается показом (`text-transform`), а не буквами; перепись экрана этого не видит и видеть не
  должна.
- Иначе — оставить капитель и назвать это отступлением от Fluent в теле pull request.

### Развилка 4. Табличные цифры: не берём токен Fluent

Ориентир владельца — цифры в колонке одной ширины. Fluent даёт для этого отдельный токен:

```
fontFamilyNumeric: "Bahnschrift, 'Segoe UI', 'Segoe UI Web (West European)', -apple-system,
                    BlinkMacSystemFont, Roboto, 'Helvetica Neue', sans-serif"
```

Bahnschrift есть только в Windows. На машине владельца и на снимках он не появится вовсе, а на
Windows цифры получат рисунок, отличный от рисунка подписей рядом.

- **Рекомендую отступление:** оставить нынешнее `font-variant-numeric: tabular-nums` на шрифте
  `fontFamilyBase`. Оно даёт цифры одной ширины на всех платформах.
- Иначе — взять `fontFamilyNumeric`, как написано у Fluent, и получить разный вид на разных
  машинах.

### Развилка 5. Заводить ли проверку чисел таблицы стилей

У таблицы стилей сегодня нет ни одного слома — это названное отступление прошлого куска.
Кусок S10 переводит экран на числа, у которых есть источник, и потому появляется возможность
сторожить хотя бы **их**: новая проверка читает `app/globals.css` и сверяет объявленные величины
с числами Fluent, выписанными в самой проверке.

**Чего она не докажет, и это будет сказано прямо в ней:** она не докажет, что таблица стилей
подключена, что правила применились и что вид хорош. Она текстовая. Она доказывает ровно одно:
числа в таблице стилей — те, что выписаны из документации, а не придуманные.

- **Рекомендую завести** и назвать слабость вслух: сегодня у нас ноль сторожей на этом файле,
  и один честно ограниченный лучше нуля.
- Иначе — не заводить и оставить всё на глаз и снимок, как в прошлом куске.

### Развилка 6. Прокрутка таблицы: снять `display: block`

Сегодня на экране уже 48 rem таблица товаров становится `display: block; overflow-x: auto`.
Названная владельцу цена: `display: block` снимает с таблицы табличную семантику, и числа теряют
связь с заголовками колонок для части читалок экрана.

Тот же приём можно поставить не на таблицу, а на карточку «Товары» — тогда таблица остаётся
таблицей, а прокручивается блок вокруг неё. Делается стилями, разметки не касается.

- **Рекомендую перенести.** Возвращается семантика таблицы, отступление прошлого куска
  закрывается.
- Иначе — оставить как есть.

Липкая шапка на узком экране от этого не заработает — см. раздел «Что остаётся верным».

### Развилка 7. Класть ли в репозиторий генератор снимков

Снимки в `docs/screens/` делаются вручную, и генератор в репозиторий не попал. На нём уже дважды
споткнулись: тема машины подменила «светлый» снимок тёмным, а безголовый браузер не открыл окно
уже 500 пикселей. Оба раза ошибку поймали измерением, а не взглядом, и следующий заход рискует
теми же двумя.

- **Рекомендую положить** генератор рядом со снимками (`docs/screens/`), чтобы обе ловушки были
  закрыты кодом, а не памятью.
- Иначе — сделать снимки одноразовым скриптом вне репозитория, как в прошлый раз.

| Что | Чем сторожится |
|---|---|
| подписи «(по обороту)» и «от чистой выручки» | перепись экрана + принятые проверки S5 |

## Чем доказывается главное

Главный риск куска: показанное поехало, а в слое метрик не поехало ничего. И второй: принятое
утверждение тронуто ради зелени.

| Утверждение | Наблюдение, а не пересказ |
|---|---|
| разметка не тронута | `git diff main..HEAD -- app/page.tsx app/refresh-panel.tsx app/logout-button.tsx app/login app/layout.tsx` пуст; код возврата снимается отдельной строкой |
| ни одно принятое утверждение не тронуто | дифф по `__tests__/` не содержит ни одной удалённой или изменённой строки — считается механически, число выводится в тело pull request |
| ни одна проверка не пропала | `npm test` даёт **не меньше 743** проверок в **58 файлах**, код возврата 0 |
| перепись экрана зелена | гоняется **первой** после каждой правки вида, утверждения не смягчаются |
| числа не поехали в источнике | пустой `git diff` по запретному списку |
| числа не поехали на экране | вывод `npm run metrics` за март до и после — `diff` двух файлов пуст, код возврата 0 |
| загрузка не поехала | живой прогон: 4 файла, 279 строк сырья, 186 после свёртки копии |
| механизмы прежних кусков живы | все шесть списков сломов (`s3`…`s9`) гоняются **один раз, на голове, которая пойдёт в слияние**, и возвращают ноль |
| новые числа вида взяты из документации | проверка стилей — если владелец примет развилку 5 |
| вид вправду хорош | снимки в обеих темах и на узком экране + глаз владельца |

Порядок работы после каждой правки вида — жёсткий: сначала перепись, потом `npm test`, и только
потом снимок. Код возврата снимается отдельной строкой сразу после команды; ворота через конвейер
не проверяются.

**Если оформление потребует тронуть проверку счёта — это находка к владельцу, а не мелочь по
дороге.** Кусок останавливается и спрашивает.

## Сломы

Своих сломов у куска мало нарочно: разметка не меняется, значит новых механизмов нет. Ломается
то, что кусок вправду заводит.

| Что ломаем | Что обязано покраснеть |
|---|---|
| подменить величину смыслового цвета в таблице стилей на выдуманную | проверка чисел таблицы стилей (развилка 5) |
| подменить размер основного шрифта на не из шкалы Fluent | она же |
| убрать правило фокуса | *слома нет — сказано вслух: правило фокуса сторожится глазом и снимком* |

Плюс — и это главная работа по сломам в куске — **все списки прежних кусков гоняются целиком на
голове слияния**: `s3-drive`, `s4-facts`, `s5-metrics`, `s6-access`, `s8-holes`, `s9-screen`.
Их вывод с кодом возврата идёт в тело pull request одним списком вместе с таблицей выше.

Слома на «таблица стилей подключена» не заводится и в этом куске: проверка, читающая ввоз в
исходном тексте, доказывала бы наличие строки, а не наличие вида.

## Что остаётся верным с прошлого куска

Владелец просил назвать это отдельно — здесь и в теле pull request.

**1. Таблица стилей сломом не сторожится; вид доказывается снимком и глазом.**
Остаётся верным. Новое оформление закрывает от этого **одну узкую полосу и только её**: если
владелец примет развилку 5, числа в таблице стилей (цвета, размеры, скругления, отступы) получат
проверку на совпадение с документацией Fluent, и подмена величины на выдуманную станет красной.
Что таблица подключена, что правила применились и что вид хорош — по-прежнему не доказано ничем,
кроме снимка и глаза.

**2. Прилипшая шапка таблицы не работает на узких экранах.**
Остаётся верным, и Fluent этого не закрывает. Причина неустранима без обёртки в разметке: пока
таблица (или её карточка) — контейнер горизонтальной прокрутки, вторая ось перестаёт быть
`visible`, и `sticky` считается от прокрутки этого контейнера, которой по вертикали нет.
Развилка 6 закрывает **другую** названную цену того же приёма — потерю табличной семантики, — но
липкую шапку не возвращает. Обёртка в разметке вернула бы её и порвала бы якоря сломов; цена
названа, выбор прежний.

## Пути, ни разу не виденные в настоящих данных

Владелец смотрит на приёмке именно сюда. Список унаследован от S9 и в этом куске не меняется:

- доля честности, равная нулю или ста процентам;
- отрицательная прибыль на экране — вид минуса проверен только на выдуманной раскладке;
- экран на месяце, где заказов нет вовсе — пустая таблица товаров;
- отказ базы при открытой странице отчёта.

Добавляется своё, от вида: **тёмная тема на боевом адресе**. Снимки делаются на машине владельца
принудительной темой, а как боевой экран выглядит у него в браузере при системной тёмной теме —
не видел никто.

## Снимки

Обновляются целиком: семь состояний × две темы + узкий экран. Пути назову в отчёте, владелец
смотрит сам.

Две ловушки, на которых снимки уже спотыкались, закрываются заранее:
тема задаётся принудительно и проверяется сравнением хешей светлого и тёмного файлов (равные

## Куда смотреть первым делом

1. **Пустой дифф по разметке.** Это главное обязательство куска. Если в диффе появилась хоть одна

## Изменения принятых решений — после приёмки контракта

> Отдельным разделом, а не правкой текста выше: контракт остаётся таким, каким его приняли, а этот
> раздел говорит, что из принятого больше не действует и почему. Контракт, который молчит об
> отменённом решении, хуже отсутствующего: по нему будут читать замысел.

### 9 сентября 2026 года — развилка 1 отменена владельцем

**Было принято:** вариант А — холст и карточка одного цвета `NeutralBackground1`, карточки
разделяются рамкой `1px NeutralBackground1Pressed`, скруглением 8 и тенью `shadow4`.

**Причина отмены:** заказчик прислал образец вида, и владелец отменил свой ответ на развилку 1.

**Действует:**

| Что | Как |
|---|---|
| холст | `colorNeutralBackground4` — серый |
| карточки | `colorNeutralBackground1`, **без рамок** |
| тень карточки | `shadow8` |
| скругление карточки | 12 — `borderRadius2XLarge` |
| внутренний отступ карточки | 20 — `spacingHorizontalXL` |
| карточка «Итог» | на смысловом цвете, текст белый |
| акцент | остаётся синим Fluent; индиго образца не берётся |

Дельты, графики, кольцевые диаграммы, вкладки и аватар с образца не делаются: это новые числа и
новая разметка, то есть отдельный кусок про содержание.

**Что это значит для цитат выше.** Условие «Low elevation ramp» называет для карточек без рамки
в светлой теме `shadow4`, а для карточек вообще в тёмной — тоже `shadow4`. Мы берём `shadow8` по
образцу заказчика. Отступление «рамка и тень одновременно» после отмены не исчезло, а сменило вид.

### 10 сентября 2026 года — значения смыслового цвета в таблице «Цвет» были неверны

**Что неверно в таблице выше:** шесть строк бренда — `BrandBackground`, `BrandBackgroundHover`,
`BrandBackgroundPressed`, `BrandBackground2`, `BrandForeground1`, `BrandStroke1` — в обеих темах.
Они выписаны из **комментариев** в `alias/lightColor.ts` и `alias/darkColor.ts` (строки вида
`colorBrandBackground: brand[80], // #0078d4 Global.Color.Brand.80`), а не из значения. Значение
берётся из палитры бренда, по которой строится тема, и для веба это `brandWeb`
(`themes/web/lightTheme.ts`: `webLightTheme = createLightTheme(brandWeb)`; тёмная —
`createDarkTheme(brandWeb)`).

**Нашёл** рецензент без контекста автора; проверено по `microsoft/fluentui` на коммите
`43665d5fb41408837ad1e85eb662575da9e0c4d0`.

| Токен | Светлая: выписано → по источнику | Тёмная: выписано → по источнику |
|---|---|---|
| BrandBackground | `#0078d4` → `#0f6cbd` | `#106ebe` → `#115ea3` |
| BrandBackgroundHover | `#106ebe` → `#115ea3` | `#0078d4` → `#0f6cbd` |
| BrandBackgroundPressed | `#004578` → `#0c3b5e` | `#004578` → `#0c3b5e` |
| BrandBackground2 | `#eff6fc` → `#ebf3fc` | `#002848` → `#082338` |
| BrandForeground1 | `#0078d4` → `#0f6cbd` | `#2899f5` → `#479ef5` |
| BrandStroke1 | `#0078d4` → `#0f6cbd` | `#2899f5` → `#479ef5` |

Остальные строки таблицы — нейтральные и красная палитра — сверены тем же разбором и совпали.
**Решение владельца:** привести к источнику, и у каждой величины проверки чисел — внешний якорь:
репозиторий, коммит, файл, звено.

Отсюда же неверным стал вывод, стоявший в разделе про контраст в плане и в документах куска:
«белое по смысловому цвету — 4,53 : 1, запаса нет». Настоящий цвет даёт 5,38 : 1 в светлой теме и
6,66 : 1 в тёмной (наш замер с отрисованной страницы).

### 10 сентября 2026 года — граница куска расширена словом владельца

Граница выше говорит: «Открывается ровно одно: `app/globals.css`» плюс новые файлы рядом. Вне её

# S3 — загрузка папки `ads-exports` с Google Диска. План работ

> **Для исполнителя:** план выполняется задача за задачей. Шаги отмечаются галочками (`- [ ]`).
> Каждая задача заканчивается коммитом и проверяемым результатом.

**Цель:** одна команда читает все файлы папки `ads-exports` на Google Диске и кладёт их строки
в `raw.ads` **одним** вызовом `raw.replace_entire_ads_folder`, ничего не исправляя; запущенная
дважды подряд, не меняет в базе ни строки, ни байта, и это видно из вывода самой команды.

**Устройство:** загрузка — функция, команда — обёртка; кнопка S5 позовёт ту же функцию.
Читается список папки, потом каждый файл байтами; пишется одним вызовом функции S1. Путь к базе —
тот самый, что написан в S2, без единой правки.

**Инструменты:** `google-auth-library` (уже стоит), драйвер `pg`, vitest, PostgreSQL 15.
Новых зависимостей не появляется: разбор CSV пишется сам, он в тридцать строк, а внешняя
библиотека принесла бы свои правила про пустые строки и типы, которых сырому слою не нужно.

**Контракт:** `.contracts/s3-drive.md` на ветке `contract/s3-drive` (коммит `0cf87c2`).
План спорит с контрактом, а не заменяет его: исполнитель читает оба.

## Общие ограничения

- Работа `ci` не переименовывается и не делится надвое. Новых шагов в ней не появляется.
- `lib/db-url.ts`, `scripts/db-reset.ts`, `lib/ingest/target.ts`, `lib/ingest/load-sheets.ts`,
  `scripts/ingest-sheets.ts`, миграции и посев не меняются ни на строку. Если задача упирается
  в необходимость их поправить — это стоп-сигнал, а не повод править.
- В `raw.ads` пишет только `raw.replace_entire_ads_folder`, и зовётся она **ровно один раз**
  за загрузку, снимком всей папки. Это обязательство контракта S1.
- Грязь источника не чинится: значения полей доезжают в базу посимвольно.
- Дедупликации нет. Обе выгрузки `meta` ложатся целиком.
- Площадка из имени файла не выводится.
- У Google запрашивается область только на чтение Диска. Кода записи в Google нет.
- Тесты пишутся до кода и сперва краснеют. Красное показывается, потом зелёное.
- Подставка изображает только то, что наблюдалось у настоящего Google (см. «Образец ответа»).

## Признак того, что S2 не сломан

Задачи 1 и 2 трогают код, которым пользуется загрузка Таблицы. Признак сохранности один и
проверяемый: **проверки S2 остаются зелёными без единой правки**. Если хоть одну проверку
пришлось тронуть — поведение S2 изменилось, и это находка, о которой говорят владельцу, а не
мелочь, которую подгоняют.

## Образец ответа Google, наблюдавшийся живьём

Разведка 1 сентября 2026 года сходила в папку ключом служебного аккаунта. Подставки в проверках
изображают ровно эту форму и ничего сверх неё.

Список (`files.list`, одна страница, `incompleteSearch: false`), по файлу такой записи:

```json
{ "id": "…", "name": "meta_2026-03.csv", "mimeType": "text/csv", "size": "2908",
  "md5Checksum": "cdc8a897b00071eae150627139dbb287",
  "sha256Checksum": "670ba760e0f338a21239fb7ac74194ef13b8b35ae775784fa188091eec203d7e",
  "trashed": false, "capabilities": { "canDownload": true } }
```

Скачивание (`files.get?alt=media`): код 200, заголовок `content-type: text/csv`, тело — байты.
Все четыре файла папки: `google_2026-03.csv` 1699 байт, `meta_2026-03.csv` 2908 (CRLF),
`meta_2026-03 (1).csv` 2814 (LF), `pinterest_2026-03.csv` 986. Заголовок у всех —
`date,campaign,spend_usd`. Ни одной кавычки, ни одной метки порядка байтов.

**Чего живьём не наблюдалось:** файла, превращённого в Таблицу Google; папки на общем диске;
неполного списка; двух одноимённых файлов. Отказы на эти случаи проверяются **на нашей стороне** —
на списке, который мы сами и составили, — а не подставным ответом Google, которого никто не видел.

### Задача 1: одна обвязка Google на два загрузчика

**Файлы:**
- Создать: `lib/ingest/google-access.ts`, `__tests__/ingest/google-access.test.ts`
- Изменить: `lib/ingest/sheets-source.ts` (авторизация переезжает, поведение прежнее)

Загрузчику Диска нужен тот же поход в Google, что и загрузчику Таблицы, но со своей областью
доступа и с возможностью получить байты, а не разобранное тело. Второй обвязки не пишем.

**Интерфейсы:**
- `googleAuth(scope)` → объект авторизации с одной названной областью.
- `googleGet(auth)` → способ прочитать по адресу разобранное тело: `{ status, body }`.
- `googleGetBytes(auth)` → способ прочитать по адресу байты: `{ status, bytes }`.
- `sheetsAccess()` остаётся `{ get }` и собирается из `googleGet(sheetsAuth())`.

Области **не складываются**: у каждого загрузчика своя авторизация со своей областью.

**Способности тоже не складываются, и это исправление первого замысла.** Сперва я собирался
отдавать обоим загрузчикам один объект `{ get, getBytes }`. Это изменило бы поведение S2:
там есть проверка «настоящий доступ умеет только читать», которая смотрит на состав объекта
целиком, и она бы покраснела. Загрузчику Таблицы способность качать байты не нужна ни для чего,
значит правильный ответ — не править проверку S2, а не давать ему лишнего: каждый загрузчик
собирает себе объект ровно из тех способностей, которыми пользуется. Доступ к Диску — `{ get,
getBytes }`, потому что список приходит разобранным телом, а файл байтами.

### Задача 5: загрузчик

**Файлы:**
- Создать: `lib/ingest/load-ads.ts`, `__tests__/ingest/load-ads.test.ts`

Здесь сходится всё: цель, чтение папки, разбор файлов, одна запись.

**Интерфейсы:**
- `ingestAdsFolder(deps?)` → отчёт: цель; по каждому файлу — байт, прочитано, записано,
  пропущено пустых, лишние столбцы; список пропущенных файлов; по `raw.ads` — количество строк
  и время последнего изменения.
- `deps` — источник папки, соединение с базой, `announce`. У всех настоящие значения по
  умолчанию: вызов без аргументов идёт настоящим путём.

**Порядок работы:** определить цель → объявить её → прочитать список и **все** файлы → разобрать
все → снять переменные `PG*` → соединиться → `begin` → **один** вызов
`raw.replace_entire_ads_folder` со строками всех файлов → счётчики → `commit`. Любая ошибка
разбора случается до соединения.

- [ ] **Шаг 1: написать падающие проверки**

Проверки идут на живой локальной базе через подставленный источник папки, внутри транзакции
с откатом (`inRollback` из `__tests__/db/support.ts`).

| Что | Ожидание |
|---|---|
| четыре файла | их строки легли в `raw.ads`, содержимое совпало посимвольно |
| **один вызов** | среди посланных запросов ровно один `raw.replace_entire_ads_folder` |
| соседние таблицы | шесть сырых таблиц Таблицы не тронуты |
| второй прогон того же снимка | **содержимое `raw.ads` совпало целиком, включая `updated_at`** |
| исчезнувший из папки файл | его строк в таблице нет |
| ошибка разбора одного файла | до базы не дошло: соединение не открывалось |
| какие операторы посланы | только `begin`, один вызов функции, чтение счётчиков, `commit` |
| имя со скобками и пробелом | доехало посимвольно |
| обе выгрузки `meta` | легли целиком, по 93 строки, ни одна не отброшена |

Идемпотентность доказывается сравнением содержимого, а не количеством строк.

## Отложено на потом — в тело pull request списком задач

- **Снимок папки не атомарен.** Список — одно обращение, скачивание — ещё по одному на файл.
  Сверка размера и контрольной суммы ловит файл, изменившийся между ними, но не ловит файл,
  **добавленный** после того, как список получен: он приедет следующим прогоном. Пакетного
  снимка папки Drive API не предлагает.
- **Папка на общем диске не читается.** Список запрашивается без `supportsAllDrives` и
  `includeItemsFromAllDrives`; сейчас папка на личном Диске и без них видна целиком. Если её
  перенесут, список вернётся пустым, и спасёт только наш собственный отказ «ноль файлов `.csv`».
  Средство — два параметра в запросе.
- **Отказ на документе Google проверен только с нашей стороны.** Испытан отбор по типу из
  списка; поведение Google при `alt=media` на таком файле живьём не наблюдалось, и подставки
  для него не ставили нарочно.
- **Замок на разрушающие операторы по-прежнему отсутствует.** Загрузчик ходит в базу
  полноправным пользователем; наблюдение за посланными запросами — не запрет базы, а обещание
  кода. Та же отложенная задача, что и у S2: своя роль, функции S1 с правами определяющего и
  жёстким путём поиска.
- **Две загрузки разом.** Загрузчики Таблицы и рекламы пишут в разные таблицы и друг другу не
  мешают, но два прогона одной и той же загрузки одновременно (две нажатые кнопки на S5) не
  проверялись ни разу.

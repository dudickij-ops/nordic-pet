# S1 — база: две схемы, запись снимка, посев. План работ

> **Для исполнителя:** план выполняется задача за задачей. Шаги отмечаются галочками (`- [ ]`).
> Каждая задача заканчивается коммитом и проверяемым результатом.

**Цель:** одна команда `supabase db reset` поднимает базу с нуля — схемы `raw`, `fact`, `dev`,
по семь таблиц данных в двух схемах, семь функций записи снимка источника и посев
демонстрационных строк, — а проверки pgTAP в `ci` краснеют, если это перестало быть правдой.

**Устройство:** сырой слой повторяет источник строками текста и опознаёт строку адресом в
источнике; слой фактов повторяет его состав, но с типами, явной валютой и внешним ключом на
сырую строку с каскадным удалением. Запись снимка (вставить новое, обновить изменившееся,
удалить исчезнувшее) живёт функциями в базе, а не в загрузчиках, поэтому S2 и S3 не смогут
написать её каждый по-своему.

**Инструменты:** Supabase CLI, Docker, PostgreSQL, pgTAP, GitHub Actions.

**Контракт:** `.contracts/s1-tables.md` на ветке `contract/s1-tables` (коммит `d28ea00`).
План спорит с контрактом, а не заменяет его: исполнитель читает оба.

## Общие ограничения

- Проверка отчитывается под именем ровно `ci`. Новые шаги дописываются в существующую работу
  `ci` в `.github/workflows/ci.yml`. Работу не переименовывать и не делить надвое.
- Загрузчиков нет: ни клиента Google, ни чтения `.env.local`, ни обращения к сети.
- Правил счёта нет: разбор грязных значений — работа S4.
- В схеме `raw` все колонки источника имеют тип `text`. Исключение — адресные колонки `row_no`,
  `file_name` и служебная `updated_at`.
- Ни одна колонка, хранящая число источника, не объявлена `not null` и не имеет умолчания.
  Адресные колонки — наоборот, обязаны быть заполнены.
- Функция записи снимка отвергает пустой снимок ошибкой.
- Строка переписывается только при отличии содержимого: `where старое is distinct from нового`.
- Посев пишет сырьё только через `raw.replace_*`, не собственными вставками.
- `supabase db push` не выполняется: миграции в облачный проект в этом куске не уезжают.
- `npm run lint`, `npm test`, `npm run build` остаются зелёными.
- Каждый файл проверки pgTAP имеет вид `begin; select plan(N); … select * from finish();
  rollback;` — это требование pgTAP, и число `N` обязано совпасть с числом утверждений в файле.

```sql
create function raw.replace_orders(p_rows jsonb) returns void
language plpgsql
as $$
begin
  if p_rows is null
     or jsonb_typeof(p_rows) <> 'array'
     or jsonb_array_length(p_rows) = 0 then
    raise exception 'пустой снимок источника для raw.orders: загрузка отменена'
      using hint = 'ноль строк почти всегда означает сбой чтения источника, а не опустевший лист';
  end if;

  insert into raw.orders as t
         (row_no, date, order_id, sku, units, gross_eur, discount_eur, gateway)
  select (r->>'row_no')::integer, r->>'date', r->>'order_id', r->>'sku', r->>'units',
         r->>'gross_eur', r->>'discount_eur', r->>'gateway'
    from jsonb_array_elements(p_rows) as r
      on conflict (row_no) do update
         set date         = excluded.date,
             order_id     = excluded.order_id,
             sku          = excluded.sku,
             units        = excluded.units,
             gross_eur    = excluded.gross_eur,
             discount_eur = excluded.discount_eur,
             gateway      = excluded.gateway,
             updated_at   = now()
       where (t.date, t.order_id, t.sku, t.units, t.gross_eur, t.discount_eur, t.gateway)
          is distinct from
             (excluded.date, excluded.order_id, excluded.sku, excluded.units,
              excluded.gross_eur, excluded.discount_eur, excluded.gateway);

  delete from raw.orders t
   where not exists (
     select 1 from jsonb_array_elements(p_rows) as r
      where (r->>'row_no')::integer = t.row_no
   );
end;
$$;
```

бы некому.

  папки разом, ключи `file_name`, `row_no`, `date`, `campaign`, `spend_usd`.

```sql
create function raw.replace_ads(p_rows jsonb) returns void
language plpgsql
as $$
begin
  if p_rows is null
     or jsonb_typeof(p_rows) <> 'array'
     or jsonb_array_length(p_rows) = 0 then
    raise exception 'пустой снимок источника для raw.ads: загрузка отменена'
      using hint = 'снимок приходит по всей папке сразу; ноль строк означает сбой чтения папки';
  end if;

  insert into raw.ads as t (file_name, row_no, date, campaign, spend_usd)
  select r->>'file_name', (r->>'row_no')::integer, r->>'date', r->>'campaign', r->>'spend_usd'
    from jsonb_array_elements(p_rows) as r
      on conflict (file_name, row_no) do update
         set date       = excluded.date,
             campaign   = excluded.campaign,
             spend_usd  = excluded.spend_usd,
             updated_at = now()
       where (t.date, t.campaign, t.spend_usd)
          is distinct from
             (excluded.date, excluded.campaign, excluded.spend_usd);

  delete from raw.ads t
   where not exists (
     select 1 from jsonb_array_elements(p_rows) as r
      where r->>'file_name' = t.file_name
        and (r->>'row_no')::integer = t.row_no
   );
end;
$$;
```

Функция вызывает `raw.replace_*` для сырья — своих вставок в схему `raw` в ней нет — и вставляет
строки фактов сама, с `on conflict … do update … where … is distinct from …`. Первая строка тела
— требование суперпользователя.

```sql
create function dev.seed_demo() returns void
language plpgsql
as $$
begin
  if current_setting('is_superuser') <> 'on' then
    raise exception 'посев демонстрационных данных выполняется только в локальной базе'
      using hint = 'нужен суперпользователь; на платформе Supabase он не выдаётся никому';
  end if;

  perform raw.replace_orders($json$[
    {"row_no": 1, "date": "01.03.2026", "order_id": "A-1", "sku": "NP-001", "units": "1",
     "gross_eur": "10,00", "discount_eur": "", "gateway": "stripe"},
    {"row_no": 2, "date": "2026-03-01", "order_id": "A-2", "sku": "np-003 ", "units": "2",
     "gross_eur": "20,00", "discount_eur": "1,00", "gateway": "paypal"},
    {"row_no": 3, "date": "02.03.2026", "order_id": "A-3", "sku": "NP‑003", "units": "1",
     "gross_eur": "30,00", "discount_eur": "", "gateway": "stripe"}
  ]$json$::jsonb);

  perform raw.replace_opex($json$[
    {"row_no": 1, "month": "2026-03", "category": "аренда", "amount_eur": "1 234,50"}
  ]$json$::jsonb);

  -- то же для refunds, costs, fees, fx и ads;
  -- в ads — две строки meta с совпадающим содержимым и разными именами файлов

  insert into fact.orders as t
         (row_no, date, order_id, sku, units, gross, discount, currency, gateway)
  values (1, date '2026-03-01', 'A-1', 'NP-001', 1, 10.00, null, 'EUR', 'stripe')
      on conflict (row_no) do update
         set date = excluded.date, order_id = excluded.order_id, sku = excluded.sku,
             units = excluded.units, gross = excluded.gross, discount = excluded.discount,
             currency = excluded.currency, gateway = excluded.gateway
       where (t.date, t.order_id, t.sku, t.units, t.gross, t.discount, t.currency, t.gateway)
          is distinct from
             (excluded.date, excluded.order_id, excluded.sku, excluded.units,
              excluded.gross, excluded.discount, excluded.currency, excluded.gateway);

  -- то же для остальных шести таблиц фактов
end;
$$;

revoke all on function dev.seed_demo() from public;
```

Артикулы в посеве пишутся ровно так, как в источнике: `NP-001` с обычным дефисом, `np-003 ` со
строчными буквами и хвостовым пробелом, `NP‑003` с неразрывным дефисом U+2011. Сумма аренды —
`1 234,50` с неразрывным пробелом U+00A0. Это не описки, а содержание проверки: сырой слой
обязан донести их без изменений.

# Финальный отчёт — дашборд прибыли Nordic Pet

Дашборд работает на `nordic-pet.vercel.app`, закрыт входом по паролю, показывает прибыль
магазина за выбранный месяц. Работа разрезана на одиннадцать кусков; каждый прошёл контракт, план,
код и проверку кода тем, у кого не было контекста автора.

Отчёт написан по трём вопросам приёмки: **что сделал, чего не сделал, где не уверен.** Ниже них —
полный список отложенных задач и указание, где лежит след работы.

### Вид экрана — как устроен после S10

**Оформление заморожено после третьего круга проверки кода.** Третий круг нашёл дефект того же
класса, что второй: сверка рецептов Fluent полна только внутри выбранных нами диапазонов строк.
По условию, названному владельцем заранее, кусок сдаётся с ограничением: наши величины
соответствуют нашей выписке; что выписка полна и соответствует Fluent 2, доказано якорями и
человеком, а не механизмом.

| Что | Как |
|---|---|
| Откуда величины | опубликованная документация Fluent 2 и исходный текст реализации токенов `microsoft/fluentui`. У каждой величины в проверке чисел таблицы стилей стоит цепочка «файл:строка» до значения на закреплённом коммите `43665d5fb414` |
| Что выведено нами | какой ступенью шкалы набирать какую роль на этом экране — справочник даёт шкалу и роли, но не говорит, как набирать подпись «Оборот». Каждый такой выбор помечен нашим в таблице стилей |
| Своих величин, не из Fluent | семь длин — `12vh`, `19rem`, `22rem`, `26rem`, `40rem`, `48rem`, `72rem`; доводы стоят у правил. Сверх того величины из шкалы стоят местами в ролях, которых Fluent не называет, — например, толщина полосы доли `8px` и отступ обводки `1px`; **этот перечень не полон** |
| Как сверены взятые компоненты | семь компонентов Fluent — кнопка, ячейка, шапка и строка таблицы, поле ввода, разделитель, полоса прогресса — сверены по свойствам стилевых блоков с диапазонами строк: `docs/сверка/рецепты-fluent.md`. Проверка полноты выписки ответила «ВСЕГО НЕ УПОМЯНУТО: 0», код возврата 0, — вывод в том же файле; что блоки выбраны верно и итоги верны — доказано якорями и человеком, а не механизмом. Итог: совпало 41, совпало по действию 15, не взято 17, отступление 17, не применимо 29. **Третий круг проверки кода нашёл блоки вне выписанных диапазонов,** которые Fluent применяет в наших состояниях: у кнопки — отключённая главная кнопка с прозрачной рамкой (`useButtonStyles.styles.ts`, строки 420–430), фокус главной кнопки с тенью `shadow2` и двумя внутренними кольцами (473–492), скругление фокуса малой кнопки `borderRadiusSmall` (495), режим высокой контрастности отключённой кнопки (372–406); у поля ввода — цвета рамки при наведении, нажатии и фокусе (`useInputStyles.styles.ts`, строки 134–144). Они не сверены и у правил не названы — это и есть ограничение заморозки |
| Разделители неполноты | токен `colorNeutralStroke2`. У Fluent это **токен разделителя, а не фона**: компонент `Divider` в виде по умолчанию рисует им линию. Взят по назначению, а не подобран по светлоте. Прежде стоял токен фона, и в тёмной теме линия шла на 1,13 : 1 к карточке; стало 1,86 : 1 |
| Полоса доли | рецепт полосы прогресса Fluent: дорожка `colorNeutralBackground6`, заливка `colorCompoundBrandBackground` — тоже по назначению. Заливка к дорожке — 4,31 : 1 и 4,50 : 1, в погашенном блоке 5,20 и 4,06. Прежде дорожка на короткое время стояла на токене разделителя, и в погашенном блоке тёмной темы заполнение сливалось с дорожкой — 1,02 : 1; нашёл рецензент. **Цена рецепта — дорожка к карточке:** 1,25 : 1 в светлой теме и 1,15 : 1 в тёмной, наш счёт; при дорожке на токене разделителя было 1,32 и 1,86. Отсюда следует, что довод за предел ширины полосы — «глазу нужен видимый остаток» — держится на дорожке, которая почти сливается с карточкой: остаток видно главным образом по концу заливки. Под WCAG 1.4.11 дорожка не подпадает — доля напечатана рядом числом; видно ли остаток глазом, решает проход владельца по предпросмотру |
| Поле ввода на странице входа | рецепт поля ввода Fluent по строкам 57–59 блока: фон `colorNeutralBackground1`, рамка `colorNeutralStroke1`, нижняя кромка `colorNeutralStrokeAccessible`. Пустое поле узнаётся только по границе, а WCAG 1.4.11 требует у такой границы 3 : 1; было 1,53 : 1, стало 6,19 : 1. **Отступление с доводом:** линии фокуса поля Fluent нет — фокус у нас общий для всех органов управления, решение владельца |
| Правило фокуса | единственный новый механизм куска: обводка `2px` цветом `colorStrokeFocus2`; к холсту и к карточке — от 14,55 до 21,00 : 1, наш счёт. **Слома у неё нет** — это правило показа, и проверка текста доказывала бы наличие строки, а не обводки |
| Вид в целом | не сторожится ничем, кроме снимка и глаза. Сторожатся числа таблицы стилей, и сверяются они с нашей выпиской, а не с Fluent 2: совпадение выписки с источником доказывают якорь и человек |

**Отступления от буквы источников** — с доводом у правила, решением владельца или прямо «довода в коде нет»:

| Отступление | Довод |
|---|---|
| табличные цифры — `font-variant-numeric`, а не шрифтовой токен Fluent | токен начинается со шрифта, который есть только в Windows; на других машинах цифры получили бы другой рисунок |
| карточка «Итог» на смысловом цвете | справочник советует не занимать им большие поверхности; одна карточка из шести, и она главная на экране |
| холст серый, карточки без рамок, тень `shadow8`, скругление 12, отступ 20 | образец заказчика, решение владельца от 9 сентября 2026 года. Справочник называет для карточек без рамки `shadow4` |
| рамка плашки отказа — `Border2`, а не `Border1` | `Border1` к нынешнему холсту даёт, по нашему счёту по формуле контраста, 1,47 : 1, и плашка перестаёт читаться плашкой |
| выбранный месяц и ненулевые строки неполноты — насыщенность 600 | вес различает их без помощи цвета; довод у правил |
| у ссылок месяцев нет наименьшей ширины малой кнопки; у обводки фокуса нет скругления и есть отступ 1px; у кнопок кольцо фокуса снаружи, а у кнопки Fluent — внутри; поле ввода выше рецепта на 6 пикселей; у заливки полосы доли нет перехода ширины | **довода в коде нет** — названо, а не объяснено задним числом |
| полоса доли толще, шире и круглее рецепта полосы прогресса | ширина — довод у правила; толщина `8px` против `2px` и `4px` у Fluent и полное скругление — **довода в коде нет** |

**Своя ошибка куска, найденная в нём же.** Первая выписка взяла двенадцать значений смыслового
цвета из комментария в исходнике Fluent, а не из значения палитры, по которой строится веб-тема;
проверка чисел была зелёной, потому что сверяла таблицу стилей с той же выпиской. Нашёл рецензент
без контекста автора. Цвет приведён к источнику, контраст смыслового цвета стал 5,38 : 1 и
6,66 : 1 вместо прежних 4,53 и 5,26.

Второй дефект того же рода внесён куском и закрыт в нём же: заменив прозрачность отключённой
кнопки на цвета Fluent, кусок открыл дорогу правилу веса — у `button:disabled` и `button.primary`
вес одинаков, а второй стоял ниже, — и отключённый вид перестал доходить до обеих главных кнопок
приложения. Найдено перемером контраста с отрисованной страницы.

## Где не уверен

| Место | В чём неуверенность |
|---|---|
| **Развилка правил 4 и 5** | буква правила 5 снимает себестоимость возвращённых штук, буква правила 4 определяет себестоимость товара без цены как 40 % чистой выручки, из которой возвраты уже вычтены. Исполнить обе дословно значит снять возвраты дважды. Наше прочтение даёт себестоимость 6 028,11 € против 5 894,31 € — **2,22 % при пороге приёмки 0,5 %**, по прибыли разрыв 7,70 %. Направление важно: у нас себестоимость **больше**, прибыль **меньше** |
| **Заказ без ставки комиссии** | даёт ноль комиссии молча — единственное место, где ноль встал вместо «нет данных» без называния. Путь закрыт двумя отказами разбора и на мартовские числа не влияет |
| **Поведение Google на общем диске** | доказано составом наших запросов и цитатами справочника, а не живой папкой |
| **Доля честности вне 0…100** | арифметически возможна, в настоящих данных не встречалась ни разу |
| **Вид в других движках** | проверен в одном; Safari и Firefox не смотрел |
| **Тёмная тема на боевом адресе** | снимки делаются принудительной темой в файле страницы; как боевой экран выглядит в браузере при системной тёмной теме, до прохода владельца не видел никто |
| **Месяцы, кроме марта** | живьём считался только март; остальные месяцы проходили через код, но их числа никто не сверял |
| **Переменные `SUPABASE_*` при пересоздании базы** | снимаются только `PG*`; влияют ли `SUPABASE_*` на то, какие миграции применятся, не проверял никто |
| **Пометка «числа отстали» не видит удаления строки в источнике** | пометка ловит правку и дописывание строки, но не удаление: отметка свежести — время самой свежей изменённой строки сырья, а удалённая строка времени не оставляет. Наблюдение на местной базе, в транзакции с откатом: строк заказов было 4, стало 3, отметка свежести не двинулась, пометка «числа отстали» не встала. **Последствие: после удаления строки в источнике экран покажет устаревшие числа как свежие, и человек об этом не узнает.** Случается это, когда загрузка с удалением прошла, а пересборка фактов после неё — нет: отказ разбора или папки при нажатии кнопки, загрузка из терминала без разбора. Нажавший кнопку увидит отказ шага на панели; тот, кто откроет страницу после него, пометки не увидит. Найдено в S11; чинится миграцией, в S11 не чинится — задача в отложенных |

| Проверка команды зовёт файл сценария, а не строку из описания команд | тот же изъян у двух команд | опечатка в строке запуска не ловится |
| Две загрузки разом не испытывались | руки не дошли | поведение при одновременных прогонах неизвестно |
| Живая проверка на настоящем общем диске | общего диска нет | единственное непроверенное место S7 |
| Ловушка сети для загрузок на боевом пути | их боевой путь ходит в Google по-настоящему | у загрузок нет боевого двойника под перекрытой сетью |
| У доступа к Диску есть шов ради проверки, у Таблицы нет | неясно, какой приём лучше | два разных приёма для одного дела |
| Защиты S3 в приборе сломов не дописаны | решение владельца: не раздувать маленький кусок ради полноты чужого списка | семь защит S3 показаны сломами руками, но в приборе их нет |
| Нет слома на половину «что делать» в отказе про неполный список | один слом снимает обе половины разом | половинная правка отказа не покраснеет своим сломом |

### Разбор в факты

| Задача | Причина | Чем грозит |
|---|---|---|
| Отказы идут двумя волнами | вторая волна требует полностью разобранных данных | лист с обеими бедами потребует двух кругов правки |
| Долю вместо процентных пунктов не ловит ничто | порога, ниже которого ставок не бывает, нет ни в задании, ни в документации | `0.0190` пройдёт как ставка и даст комиссию в сто раз меньше |
| Строки-близнецы видны только в выводе команды | показать их на экране — это «что», а не «как» | человек у экрана о них не узнает |
| Код состояния и подлинный текст отказа базы теряются при переводе | перевод на человеческий язык съедает подробности | отлаживать редкий отказ будет нечем |
| `40P01` живьём не наблюдался | воспроизвести взаимную блокировку нарочно дорого | перевод этого кода проверен подставкой, а не настоящим случаем |
| «Боевая проверка возвращает базу такой, какой нашла» сторожится случайно | сторожит порядок файлов прогона, а он берётся из кэша длительностей | снятая уборка ловится через раз, и красным чужим, по которому причину не найти |

### Счёт и экран

| Задача | Причина | Чем грозит |
|---|---|---|
| Заказ без ставки комиссии даёт ноль молча | путь закрыт двумя отказами разбора, на мартовские числа не влияет; починка ввела бы два новых вида дыры | единственное место, где ноль встал вместо «нет данных» без называния |
| `money('')` тихо отдаёт « €» | путь сегодня недостижим | пустая строка вместо числа прошла бы незамеченной |
| Боевой вызов команды метрик в списке не повторяет сценарий целиком | та же асимметрия у трёх прежних команд | кто позовёт запись списка вместо сценария, получит не то, что ожидал |
| Проверка «слой метрик не превращает деньги в число» читает исходный текст | заменить её механизмом нечем: механизм здесь и есть система типов | проверка честно слабая и названа слабой |
| Замок обновления стоит только на пути кнопки | команды из терминала его не берут | одновременный прогон из терминала и кнопки не разведён |
| Наследственная ветка на странице отчёта | живёт ради принятой проверки S6 | убрать её значит покрасить чужую принятую проверку |
| Сторожа у серверных действий входа и выхода нет | они ничего не отдают и ничего не пишут постороннему | доказательство им одно — проход руками |
| Прибор сломов хрупок на длинном прогоне | за кусок обрывался четыре раза, оставляя правку в дереве | оборванный прогон легко принять за красное по существу |
| Пометка «числа отстали» не видит удаления строки в источнике (найдено в S11) | механизм прошлого куска, а починка требует миграции и наката в бой — решение владельца. Наблюдение: строк заказов было 4, стало 3, отметка свежести не двинулась, пометка не встала | после удаления строки в источнике экран покажет устаревшие числа как свежие, и человек об этом не узнает — когда пересборка фактов после загрузки не прошла |

### Вид экрана

| Задача | Причина | Чем грозит |
|---|---|---|
| Защиты, живущие в таблице стилей, без сломов | их две: приведение длины полосы к пределам и гашение устаревших чисел. Сломать их проверкой нельзя — нужен прогон в настоящем браузере | удаление одной строки вернёт ложь «полоса во всю дорожку при отрицательной доле», и ни один слом не увидит |
| Правка полосы доли и поля ввода круга правок 2 ничем не сторожится | откат правил дорожки, заливки и фона поля в таблице стилей не красит ни одной проверки — это правила показа. На снимках: полоса доли в обычном виде видна на четырёх — широкий и узкий экран, светлая и тёмная тема; **погашенная полоса, ради которой шла правка, не видна ни на одном** — на снимках отказа шага и «числа отстали» кадр в 760 пикселей обрывается выше неё; поле ввода видно на обоих снимках входа | погашенную полосу снова можно слить с дорожкой, и не заметит этого ни проверка, ни снимок; видит её только проход по живому экрану |
| Блоки Fluent вне выписанных диапазонов не сверены | третий круг проверки кода нашёл их после заморозки: у кнопки — отключённая главная кнопка с прозрачной рамкой (`useButtonStyles.styles.ts`, строки 420–430), фокус главной кнопки с тенью `shadow2` и двумя внутренними кольцами (473–492), скругление фокуса малой кнопки `borderRadiusSmall` (495), режим высокой контрастности отключённой кнопки (372–406); у поля ввода — цвета рамки при наведении, нажатии и фокусе (`useInputStyles.styles.ts`, строки 134–144) | наши правила в этих состояниях расходятся с Fluent, и расхождение не названо у правил; перечень найденного рецензентом не доказан полным |
| Комментарий у закрывающего утверждения проверки чисел противоречит её шапке | комментарий пишет «всякое цветовое свойство во всех правилах», шапка — что цвет ловится только в перечисленных свойствах. Верна шапка. Правка текста проверки — изменение в автоматических проверках, и в замороженном куске её нет | читающий комментарий поверит в закрытие, которого нет |
| Правила показа без слома, сверх двух защит | нижняя кромка поля ввода, которая одна опознаёт пустое поле; прокрутка таблицы на карточке — проверки и слома на возврат `display: block` таблице нет. Сломать их проверкой нельзя по той же причине | кромку можно снять, а табличную семантику на узком экране вернуть в прежний вид — молча |
| Липкая шапка таблицы не работает уже 768 пикселей | уже с этой ширины **карточка «Товары»** становится своим контейнером горизонтальной прокрутки, а внутри контейнера прокрутки прилипание считается от него, а не от страницы. Наш замер: прокрутка на 900 пикселей, при 1280 верх шапки идёт с 544 к 0, при 390 — с 773 к −127 | на узком экране числа читаются без подписей колонок |
| Сторож снимков заморожен, и он не ловит перепутанные темы | сторожа сравнивают светлую и тёмную стороны между собой, и ни одна из сторон не привязана к источнику. Заморожен после трёх кругов проверки кода: прибор съел бюджет куска | перестановка двух веток в сборке развела бы темы по неверным сторонам, и весь набор проверок остался бы зелёным. Ловит это только глаз на снимках |
| Сломы разметки трёх прежних списков гоняют один файл проверок, а не весь набор | так они заведены: `s5-metrics`, `s6-access`, `s8-holes` — девятнадцать сломов, у каждого в наборе стоит один файл | их зелень читается сильнее, чем есть: «проверено механизмов: 87» понимается как «поймано всем, что у нас есть», хотя поймано одним файлом из шестидесяти одного. Закрывается переводом на полный набор и дописыванием объявления красного — тем же приёмом, каким это сделано для `s9-screen` |
| Полоса управления распадается в двух состояниях из пяти | цена расположения кнопок в разметке: кнопка выхода, кнопка обновления и название лежат в разных ветвях и на разной глубине, и собрать их в один ряд удаётся плавающими блоками только пока между ними ничего не стоит. Единственный оставшийся путь стилями — цепочка `subgrid` через шесть уровней вложенности | на холодном открытии «Выйти» на 74 пикселя выше остальной полосы; при отказе шага название на 148 пикселей ниже кнопок |
| Во время обновления человеку не сказано словом, что оно идёт | кнопка на время работы становится отключённой, и это единственный признак; текста «обновляем» на экране нет | человек, не заметивший смены вида кнопки, нажмёт второй раз и получит отказ «занято» вместо понятного ожидания |
| Типографика и правило фокуса сломов не имеют | обе живут только в таблице стилей: сломать их проверкой нельзя, нужен прогон в настоящем браузере | снятая обводка фокуса или сбитая ступень шкалы не покраснят ни одной проверки; ловит это только глаз на снимке |
| Снимки делаются раскладкой, а не живым экраном | снимок с живого экрана потребовал бы входа и пароля | снимок и бой могут разойтись, и заметит это только глаз |
| Цитата слома `stale-class-dropped` — подстрока цитаты соседнего слома | сегодня обе однозначны | одна будущая правка этой строки потребует перевода в двух местах |
| Вид проверен в одном движке | других под рукой нет | поведение в Safari и Firefox неизвестно |

| След | Где лежит |

Порядок чтения, если время ограничено: контракт куска → тело его pull request → таблица сломов
в нём. Контракт говорит, что обещано; тело pull request — что вышло и чем доказано; таблица
сломов — что из этого проверено красным, а что осталось словами.

## Как запустить и посмотреть

| Что | Как |
|---|---|
| Адрес дашборда | `https://nordic-pet.vercel.app` |
| Вход | по логину и паролю; они передаются отдельно от этого отчёта и в репозитории не лежат |
| Что видно без входа | ничего: ни экрана, ни чисел, ни адресов, по которым страница берёт числа |
| Обновление данных | кнопка «Обновить данные» на самом экране: перечитывает оба источника и пересобирает факты |
| Месяц | берётся из адреса (`?m=2026-03`); без него показан последний месяц, за который есть заказы |

**Дашборд только читает Google и никогда туда не пишет.** У служебного аккаунта доступ
«Просмотр», и у Google запрашиваются области **только на чтение** — отдельная для Таблицы,
отдельная для Диска.

**Замок от подбора пароля запирает и нас.** Десять неверных попыток подряд закроют дашборд на
пятнадцать минут для того, кто ошибался. Это исправная работа механизма, а не поломка.

Запустить у себя: нужны PostgreSQL 15 и Supabase CLI, дальше — `npm run db:reset`, `npm test`,
`npm run dev`. Полностью это описано в README.
